# DayLine 导出数据格式说明（schemaVersion = 1）

本文说明 DayLine「导出」生成的备份包格式，方便第三方程序读取或生成兼容数据后再导入 DayLine。

代码依据：`app/src/main/java/com/dayline/backup/BackupModels.kt`、`BackupServices.kt`、`Naming.kt`。

## 1. 文件包结构

导出文件是一个标准 ZIP，文件名为 `records_yyyy-MM-dd.zip`（日期取导出当天的本地日期；同一天多次导出依次为 `_1`、`_2` …，序号超过 99 改用 `_HHmmss`）。

```
records_2026-11-14.zip
 ├─ records.json                  # 必需：全部记录（含回收站）+ 标签 + 设置
 ├─ media/images/ab/abcd….jpg     # 图片
 ├─ media/videos/ab/abcd….mp4     # 视频
 └─ media/covers/ab/abcd….jpg     # 视频封面
```

- `records.json` 放在 ZIP 根目录，UTF-8 编码，内容是格式化（pretty print）的 JSON。
- 媒体文件在 ZIP 里的路径就是 `records.json` 中引用的相对路径，两边一致，不需要再映射。
- 媒体文件名一般是该文件的 SHA-256（小写十六进制）加原扩展名，上一级子目录是 SHA-256 的前两位。**导入方不能依赖这个命名规则**：DayLine 导入时会重新计算 SHA-256，并按自己的规则存放文件。
- 只导出被记录引用到、且导出时文件确实存在的媒体；引用了但文件已丢失的媒体不会打进包里。

## 2. records.json 顶层结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schemaVersion` | int | 否（默认 1） | 格式版本，当前为 `1` |
| `exportedAt` | long | 是 | 导出时间，Unix 毫秒时间戳 |
| `settings` | object | 是 | 显示设置，见 §3 |
| `tags` | array | 否（默认 `[]`） | 标签表，见 §4 |
| `records` | array | 否（默认 `[]`） | 记录列表，见 §5 |

DayLine 解析时会忽略不认识的字段，所以第三方可以加自己的扩展字段，不会导致导入失败。

## 3. settings

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `beneficialLabel` | string | `"有益"` | 「有益」一栏显示的名称 |
| `badLabel` | string | `"糟糕"` | 「糟糕」一栏显示的名称 |
| `beneficialCustom` | bool | `false` | 用户是否自定义过 `beneficialLabel` |
| `badCustom` | bool | `false` | 用户是否自定义过 `badLabel` |

## 4. tags[]

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 标签 ID（UUID） |
| `name` | string | 标签名，DayLine 以名称为准复用已有标签 |
| `createdAt` | long | 创建时间，Unix 毫秒 |

记录通过**标签名**引用标签（见 `records[].tags`），不通过 ID 引用。

## 5. records[]

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 记录 ID（UUID）。用于跨设备合并，必须全局唯一且长期不变 |
| `content` | string | 是 | 正文 |
| `side` | string | 是 | 所在栏：`"beneficial"`（有益）或 `"bad"`（糟糕） |
| `recordDate` | string | 是 | 记录归属日期，格式 `yyyy-MM-dd` |
| `createdAt` | long | 是 | 创建时间，Unix 毫秒 |
| `updatedAt` | long | 是 | 最后修改时间，Unix 毫秒，合并时用来判断哪边更新 |
| `isDeleted` | bool | 否（默认 `false`） | 是否在回收站中 |
| `deletedAt` | long \| null | 否 | 移入回收站的时间 |
| `tags` | string[] | 否 | 标签名列表 |
| `imagePaths` | string[] | 否 | 图片路径（ZIP 内路径），按显示顺序排列 |
| `videoPaths` | string[] | 否 | 视频路径 |
| `videoCoverPaths` | string[] | 否 | 视频封面路径 |
| `mediaSha256` | object | 否 | `{ 路径: sha256小写hex }`，媒体校验信息；缺少时由导入方重新计算 |

> 注：`side` 取值以 App 内的实际写入为准；新建记录的默认值是 `"beneficial"`。

### 示例

```json
{
  "schemaVersion": 1,
  "exportedAt": 1794643200000,
  "settings": {
    "beneficialLabel": "有益",
    "badLabel": "糟糕",
    "beneficialCustom": false,
    "badCustom": false
  },
  "tags": [
    { "id": "6f1c…", "name": "运动", "createdAt": 1794600000000 }
  ],
  "records": [
    {
      "id": "0b7e3c2a-…",
      "content": "晨跑 5 公里",
      "side": "beneficial",
      "recordDate": "2026-11-14",
      "createdAt": 1794620000000,
      "updatedAt": 1794620000000,
      "isDeleted": false,
      "deletedAt": null,
      "tags": ["运动"],
      "imagePaths": ["media/images/ab/ab12….jpg"],
      "videoPaths": [],
      "videoCoverPaths": [],
      "mediaSha256": { "media/images/ab/ab12….jpg": "ab12…" }
    }
  ]
}
```

## 6. 导入时的合并规则（第三方生成数据时要注意）

1. **ID 相同**：导入数据的 `updatedAt` 比本地新时，覆盖本地记录（包括 `isDeleted` 状态）；否则跳过。
2. **ID 不同、双方都未删除**：按内容指纹去重，指纹已存在（本地已有或同一个包里已出现过）就跳过。
3. **已删除的记录**：只按 ID 合并，不做内容去重。
4. 媒体只会从 ZIP 的 `media/` 目录下解包，其他目录会被忽略；类型由路径里的 `/images/`、`/videos/`、`/covers/` 判断。损坏的文件会跳过并写进导入报告。
5. 设置单独合并（`mergeFromImport`）；数据库写入在同一个事务里完成，任一步失败会整体回滚。

### 内容指纹算法

```
normalized = content.trim() 后把连续空白替换为单个空格
           + "\u0001" + side
           + "\u0001" + recordDate
           + "\u0001" + 标签名(去掉首尾空白、去掉空串、升序排序后用 "," 连接)
           + "\u0001" + 媒体sha256(转小写、升序排序后用 "," 连接)
fingerprint = SHA-256(UTF-8(normalized))，结果为小写 hex
```

图片顺序和标签顺序不影响指纹。

## 7. 第三方实现要点

- **读取**：解压 ZIP → 解析 `records.json` → 按 `records[].imagePaths` 等路径到 ZIP 中找对应媒体。
- **生成可导入的包**：
  - 每条记录生成一个稳定的 UUID 作为 `id`，并填好 `updatedAt`；
  - 媒体放在 `media/images|videos|covers/` 下，`records.json` 里写同样的路径；
  - 建议填写 `mediaSha256`；
  - 时间戳统一用毫秒，日期用 `yyyy-MM-dd`。
- **版本兼容**：读取时先看 `schemaVersion`，遇到大于 1 的版本应提示用户，或者只读取认识的字段。
